# DR5-080 — Structured exercise targets

Domain and storage handoff for the Phase 10 editor and session tasks. This item
does not implement the final Compose designs or publish a release.

## Current contract

`Exercise` and `ExercisePrescription` contain `setCount: Int`, `reps: Int?`,
`durationSeconds: Int?`, and `weightPounds: Int?`, alongside name, notes, and
artwork. Sets must be positive. Each optional value may be null independently;
present reps and seconds must be positive. Pounds must be positive and divisible
by five. The largest representable valid weight is 2,147,483,645 lb. Duration is
also the timer duration, so there is no second stored timer value to synchronize.
Seed repetition targets are now explicit integers (12, 12, 15, and 10); no stored
target string is parsed.

The current JSON exercise is the prescription's fields plus `id` and nullable
`progression`. Custom progression contains only `steps`, each with a complete
`replacement` prescription and an ordered `insertedExercises` array. Null slots
are written explicitly. Unknown/missing fields, malformed numbers, and invalid
values are rejected at the document boundary. The older schema reader and
automatic rule types, options, fields, and calculation tests are removed.
`app/src/test/resources/structured-exercise.json` is a hand-authored current
fixture with 35/40/45 lb prescriptions and an inserted exercise.

## Repository operations

- `progressionOffer(sessionId, exerciseId)` checks completion, lease-independent
  document eligibility, unchanged snapshot/source identity, and revision lineage.
  Its custom options can be empty while a manual adjustment is still eligible.
- `offer.request(CUSTOM)` selects the first committed custom step. Application
  replaces every prescription field, retains source identity, consumes one step,
  preserves the remaining order, and inserts that step's exercises immediately
  after the source. An exhausted queue becomes null.
- `offer.manualRequest(prescription)` supplies a complete manual prescription.
  `applyProgression` validates it, preserves the queue and all existing exercises,
  and atomically writes the routine revision and a durable receipt containing the
  manual prescription. No custom step is consumed.
- `SessionEvent.ContinueWorkout` is the keep-current operation. It records only
  the handled session decision and consumes no step.
- Apply requires current session/routine revisions and a valid session lease.
  An identical retry returns its receipt; a different competing decision returns
  a conflict. Failed writes publish neither part of a change.
- `undoProgression` restores the prior complete exercise and removes only that
  receipt's insertions. Later routine mutations expire undo. Session/preferences
  writes do not. Receipts survive restart and backup/restore.
- Apply and undo leave active and completed routine snapshots intact. Restart is
  the existing explicit operation for adopting the changed live routine.
