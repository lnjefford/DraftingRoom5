## Value traces and numerical contract

* **Manual:** decimal text → `Money.parse` HALF_UP cents → repository generation check → strict codec and SQLite transaction plus append-only ledger → latest `(asOfDate, sequence)` balance → integer-cent aggregator and tax-treatment rows → confirmed classification's forecast bucket → real-dollar engine → cents rounded only at publication. Holdings never add a second balance. Archive removes current totals while preserving history.
* **Plaid:** fixed-origin HTTPS, lexeme-preserving numeric parser, USD and complete-account/holding checks → encrypted pending item before review → explicit type/tax/owner/inclusion and manual-match selection → vault revision guard and atomic reconciliation → operation receipt and same-day balance/holding idempotency → the same aggregate/capture path. Omitted accounts cannot erase last-good holdings. Reconnect invalidates older reservations; disconnect preserves history and distinguishes local removal from remote revocation.
* **RentCast:** user-confirmed address/identity → bounded decimal estimate/range → guarded property creation/refresh → property valuation ledger plus source metadata → `(value − mortgage) × ownershipBps / 10000` with HALF_UP → one owned-equity contribution, no wrapper balance. Negative current equity remains negative; only spendable modeled sale proceeds floor at zero. Mortgage payment/rate/months and plan disposition enter the forecast capture.
* **Shareworks:** selected content stream → bounded ZIP/CRC/relationship/SAX checks and required cached-result validation → transient generation-bound review → explicit confirmation → derived workbook/import metadata and active pointer in one transaction → vested value less loans for current assets → saved annual pretax/after-tax schedule, date/coverage validation, real-dollar deflation and timed liquidation for Forecast. No local Epic assumptions, macro/formula execution, raw file persistence or inferred missing years.
* **Plan:** validated complete draft → one revision → committed change signal → detached forecast input generation → bounded cancellable worker calculation → request and repository generation checked at publication. Scenario application changes one typed delta with generation/revision CAS. Settings are now labeled with the revision that actually produced a displayed result.

The integrated fixture is **7,855,000 cents tracked** and **7,655,000 cents forecast-eligible**: 100,000 manual Roth + 200,000 excluded linked pre-tax + 55,000 Epic + 7,500,000 owned property equity. The six treatment rows must sum exactly to tracked assets.

## Security and privacy review

The approved topology remains phone-only. No backend, hardcoded provider secret or signing material was introduced. Plaid profiles/items and RentCast keys are AES-256-GCM encrypted with a nonexported Android Keystore key; authenticated metadata includes schema, provider, environment, local ID and revision. Atomic ciphertext files and the financial SQLite DB/WAL/SHM live outside backup. Provisioning/replacement requires screen lock and device authentication. Background use is permitted after first unlock without per-request authentication, as explicitly approved; this does not protect against a compromised app process.

Transport uses fixed HTTPS origins and enum endpoints, no redirects/cache, bounded time/response size, safe local errors and wiped byte buffers where possible. Managed Strings/SDK/HTTP copies cannot be proven erased from memory. RentCast address queries necessarily leave the phone. WorkManager input contains opaque UUIDs only. No ad-hoc production Retirement logger was found. SDK-internal/live logging remains an external validation limit.

Both backup XML files remain the unchanged Fitness-only three-file allowlist. Fitness documents contain no Retirement subtree. Native secure-window assertions and synthetic canary scans supplement source checks; they do not establish real cloud/device-transfer transport behavior. Test-only screenshots explicitly replace all content with hand-authored fixture state before temporarily allowing capture, and reassert/restore FLAG_SECURE. They are not captures of private financial state.

Plaid's [Accounts API documentation](https://plaid.com/docs/api/accounts/) confirms cached `/accounts/get` balances, liability-sign semantics and that `last_updated_datetime` is narrowly available. A successful fetch therefore means last accepted provider data, not a real-time institution balance. A direct attempt to open the RentCast property-value documentation with the browsing tool failed; local provider contract/code and fixtures were reviewed, but live service conformance is not claimed.

The browsing tool successfully fetched all four Library landing pages on 2026-09-21: [SSA retirement planning](https://www.ssa.gov/retirement/plan-for-retirement), [Medicare basics](https://www.medicare.gov/basics/get-started-with-medicare), [IRS retirement plans](https://www.irs.gov/retirement-plans), and [Investor.gov retirement savings](https://www.investor.gov/introduction-investing/investing-basics/investment-accounts/tax-advantaged-accounts/retirement-savings).
