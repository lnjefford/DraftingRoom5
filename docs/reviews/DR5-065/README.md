## Findings and corrections

1. **Workout prescriptions omitted structured measurements.** Weight progression changed persisted pounds but the active/completed/upcoming exercise cards and routine cards continued to show only the unchanged free-text target. Added structured measurements to those surfaces and their semantics. The free-text target is retained; no numeric parsing is introduced.
2. **Editing a terminal custom prescription erased its measurements.** Once the final step cleared the progression rule, ordinary draft conversion dropped pounds/seconds. Draft conversion now retains values independently of whether a rule is enabled; retained values remain editable with progression off. Tests cover a real final custom step followed by a notes edit.
3. **The editor advertised an unavailable increase-both result.** Its independent arithmetic also accumulated binary decimal error and could format very large integral pounds as `Long.MAX_VALUE`. Preview now uses the same `progressionOptions` as commit, displays actual alternatives and bound exhaustion, and formats decimal values without narrowing to Long. Tests cover 0.1 + 0.2, bounds, and 1e20 round trips.
4. **Single-choice acceptance had no visible exact preview.** Only a TalkBack description exposed the result, and additions were omitted. The outlined Ready action now includes the replacement, notes, timer and ordered additions. The title still has no explanatory subtitle; Continue remains the filled-blue primary action. Added four custom decision screenshot cases.
5. **Rotation could discard unsaved custom changes.** The outer custom rule, working step sequence and inserted-exercise list used plain `remember`. Added structural saved-state savers, including empty drafts and recursive insertions, with round-trip tests.
6. **Failure recovery was obscured or unavailable.** Apply errors appeared behind the modal; failed Undo said to retry after consuming the only action. Errors now appear inside the decision sheet, and failed Undo offers another Undo action. Busy modal dismissal is gated; stale callbacks with existing receipts do not replay success feedback. Voice/timer feedback ownership pauses while the progression decision is present.
7. **Deep custom insertion trees could save unreadable data.** The strict reader enforces 32 JSON container levels, but the writer previously checked only bytes and domain values. The writer now checks the same grammar/depth limit with one reserved backup-envelope level. The audit tests increasing recursive depths: every accepted encoding must round-trip through current document and backup; excessive depth must fail before persistence. This preserves the reader limit rather than weakening it.
8. **Inserted rows lacked keyboard reorder, and index-keyed steps could change focus identity.** Added Ctrl+Up/Down to insertion cards, stable saved UI keys for steps, stable composition keys for additions and identity-based resolution in move callbacks. Consecutive drag updates resolve the current location of the same item instead of moving whichever item occupies its previous index. Domain ordering tests remain applicable; native keyboard/TalkBack traversal is not inferred from host screenshots.

## Native harness and limitations

`ProgressionNativeAudit` is Android-test-only and is selected through the existing instrumentation runner with `-e audit progression`. It mounts the production guided-session destination in a real activity, uses an isolated `AtomicJsonStorage` file under `files/progression-audit`, and drives Android accessibility actions. It does not replace the user's training document. Captures and assertions cover Continue, custom apply/insertion, snackbar Undo and explicit heavier/shorter acceptance.

This harness does not claim physical exercise safety, medical suitability of increments, audible speech quality, physical vibration, full TalkBack traversal or universal device/API coverage. Host state/repository tests and native interaction checks are identified separately. Saved-state serializer tests are not represented as a full operating-system process-kill test.
