## Outcome and corrections

No known critical or high-severity application defect remains after the fixes below. This is a source, unit-test, Android lint/build, and native host-render review. ADB reports no connected device; it is not a physical-device acceptance certificate.

- **Recovery durability:** replaced copy/delete/rename backup rotation with the same AtomicFile-backed storage boundary used by the current document. Validate a latest snapshot before rotating it, so corrupt latest data cannot overwrite the readable previous snapshot. Rotation and restoration remain serialized across managers. Regression tests cover failure writing either slot, corrupt latest plus a failed new write, successful recovery after failure, and invalid new snapshots. Power interruption and actual disk-full behavior still require Android testing.
- **Calendar lifecycle:** Dashboard follows today across midnight and resets selections that have fallen outside its displayed week. It preserves an explicitly chosen date within that week. Refresh the date on foreground entry and every 30 seconds while focused; fixed render time remains deterministic. Added midnight, week-boundary and explicit-selection regressions.
- **Privacy accessibility:** replaced the non-scrollable Health Connect rationale layout with a conventional secondary app bar and scrollable content. Back and Done both finish the activity. Text explains the actual read-only data use and backup exclusion. Added compact, tall, 2x-font, and landscape native references.
- **Honest recovery feedback:** failed manual backups with automatic backups off now instruct the user to retry manually rather than promising a scheduled retry. Added a regression.
- **Release automation:** the Dependabot merge request now supplies the exact commit SHA from the successful verification run. If the PR head changes between inspection and merge, GitHub must reject rather than merge an unverified replacement. A static workflow guard check verifies the SHA binding.
- **Obsolete UI:** deleted FoundationDestinationScreen and its unused ExerciseEditor route/serialization. The actual exercise builder remains saved parent-owned editor state. Removed its obsolete route cases from navigation tests; no migration reader or alias was added.

## Cross-cutting review

- **Ownership and simplicity:** AppRepository is the process-shared committed authority; generation checks protect editor writes and session leases protect restored/reset documents. Compose owns view/draft state and mirrors successful committed results. Session commands run on IO and use monotone elapsed deadlines. The implementation uses an explicit saved Compose stack and parent-owned exercise screen rather than introducing every proposed state-holder class. This is an implementation simplification, not a second data model.
- **Privacy and security:** manifest permissions are read-only Health Connect, internet, vibration and user-mediated package installation. Package visibility uses MAIN/LAUNCHER plus Health Connect/TTS queries, not QUERY_ALL_PACKAGES. Linked intents are package-bound and reject unsafe URI forms. Update downloads use the fixed GitHub release source, enforce a size limit, and verify package/newer code/exact signer set before installer launch and again on permission return. App-owned snapshots exclude measured health data and permissions; Android backup allowlists include only the two snapshots/status and require encryption for cloud backup. No credentials or signing material are part of this change.
- **Storage and exceptional states:** strict current-only document/envelope fields, duplicate-key/grammar/depth/UTF-8/size checks, explicit corruption recovery and commit-before-success behavior remain. DR5-029 contributes 18 named exceptional fixtures and 72 renders. Those are presentation fixtures, not proof of Android permission dialogs or every live recovery interaction; the physical checklist below remains authoritative.
- **Performance:** bounded documents, stable list keys, lazy long screens, sized artwork and bounded timer indicators are present. Timer ticks write at phase/cue changes rather than every display frame. Some general plan/settings/manual-backup operations are synchronous; measure them with large valid documents on a slow device before calling storage latency acceptable. No device frame-time, memory, power or ANR measurements are claimed.
- **Visuals/accessibility:** reviewed core Dashboard, large-text exercise/session screens, exceptional landscape/large-text sheets, routine/exercise crop sheets and launcher-mask sheet. New privacy references receive individual inspection. Navy/ivory contrast, reduced decorative art at large fonts, native scroll containers, non-color status and 48 dp actions are present. Host references cannot prove TalkBack focus, touch reachability, system font/display scaling or IME behavior.
- **Artwork provenance:** catalog generation/export information is recorded in docs/artwork/AssetLedger.md and bundled font license in third_party. The older Dashboard hero's original prompt/tool metadata was not retained; the ledger explicitly records that gap. This review does not invent provenance. No design mockup is used as runtime UI.

## Prioritized physical-device checklist

ADB check this run: no attached device. Record device model, Android/API, app version, steps and outcome for each check; keep unavailable cases explicit.

1. **P1 — Recovery and persistence:** kill the process after completing a set, during Get ready/running/finished, and immediately after Finish. Resume the exact snapshot/occurrence; never replay missed cues or complete a set from elapsed time. Reboot to invalidate the timer origin. Interrupt backup rotation and simulate storage full: either current or previous valid snapshot must remain readable and failed saves must not publish success. Restore with a saved session and verify its old timer is cleared; cancel restore/reset without changing data.
2. **P1 — Health permissions/privacy:** on supported pre-14 and 14+ devices test unavailable/update provider, each granted/revoked metric, optional history access and older Withings data, no-data and read-error recovery. Visit rationale from Android permissions at 2x text and in landscape; scroll to Done and verify Back. Confirm app snapshot/Android transfer contains no measured health data or permissions.
3. **P1 — Installation and linked apps:** install the next signed APK over v0.22.0, deny then allow unknown-source permission, cancel and retry installation. Wrong-package/signer/non-newer APK checks must reject. Launch both built-ins and a newly selected app, fail a deep link, uninstall/reinstall, and exercise Change app/store recovery without losing the routine.
4. **P1 — Accessibility/input:** TalkBack traversal and single actions for cards, switches, charts, timers, dialogs and picker rows. Verify focus after reorder, exercise completion/edit/delete, artwork return and tab changes. Test Move up/down, Ctrl+arrows, D-pad, drag cancel/edge scrolling and all weekdays. Use compact/tall/landscape, 2x text, display scaling, IME and cutouts; essential actions must remain reachable.
5. **P2 — Timing and performance:** foreground/background during countdown/finish, screen lock, incoming dialog/call, rapid taps and voice/haptics off/system-off. Check reduced motion. Profile cold load, scroll and plan/settings/backup writes with a large valid history on a low-end device. Confirm ordinary drafts survive rotation/process recreation without saved-state-size failures. Leave Dashboard open across midnight/week rollover and a timezone change; explicitly selected in-week days must remain stable.
6. **P2 — Release presentation:** inspect launcher circle/squircle/rounded-square/OEM/themed icons at physical small sizes, all artwork crops, source/date locale labels, and source freshness warnings.
