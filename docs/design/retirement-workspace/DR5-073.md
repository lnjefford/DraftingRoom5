## Parsing and data ownership

`retirement/importer/ShareworksImporter.kt` reads a single user-selected content stream on an IO dispatcher. Its native JVM/Android ZIP and SAX implementation does not need Apache POI, a server, a spreadsheet runtime, network access, macro execution, or formula evaluation. File extension/MIME filtering is only a picker hint: the archive must identify a macro-enabled OOXML workbook and contain the supported 2026 Shareworks sheets. VBA entries are never executed.

The supported cell map matches the pinned reference parser: consolidated E6, B/C/E/F/G/H/I/J/L/M rows 12–18 and totals row 19; summary C9–C13/C38/C41/C44/C47; annual row 15 and rows 19/23/24/31/36/37/46/47/48/49/51; history column D from row 8. Required values are never defaulted to zero. Decimal quantities/rates and HALF_UP integer cents preserve workbook results. Numeric OOXML cells permit bounded scientific notation used by spreadsheet writers; textual numeric cells use strict decimal/grouping syntax, and persisted values never use exponent notation. Excel's 1900/1904 date systems and ISO dates are supported; the fictitious 1900 leap day is rejected.

Validation rejects absent/error/nonfinite formula caches, recalculation-required cells, manual/incomplete/forced recalculation flags, invalid dates and ranges, inconsistent totals, duplicate/out-of-order years and incomplete annual columns. It never recomputes tax, sale, vesting or growth. Formula freshness cannot be independently proven when a workbook falsely presents internally consistent old caches with no recalculation flags; users must recalculate and save in Excel. The app explicitly describes its data as saved workbook results, not live prices or independently recalculated figures.

Bounds are 20 MiB compressed, 100 MiB expanded, 2,000 entries, 100:1 per-entry expansion, 16 MiB per retained XML part and 32 MiB total retained XML (a stricter memory cap for Android; the synthetic fixtures use under 10 KiB), 100,000 cells per inspected sheet, 500,000 XML nodes, depth 64 and 500 annual columns. Central-directory/trailer, sizes and CRCs are checked; truncated/encrypted archives, duplicate entries/cells, traversal and external workbook relationships are rejected. DTDs and entity resolution are disabled/rejected. Required fields are retained only in a normalized candidate. Missing optional annual/history data has explicit unavailable states; a single history observation is not zero volatility. No missing years are extrapolated.

## Atomic replacement and privacy

Selection and validation do not change accepted values. Review binds the candidate to the repository generation and prior active import. An explicit Accept/Replace action appends the derived import ledger, full normalized model, active pointer and success metadata in the existing single SQLite transaction. Conflicting reviews cannot publish mixed data. A repeat of the active digest is idempotent. Failure preserves prior accepted values/time and records only a local error category. Import history remains append-only, as established by DR5-069.

Only derived models and provenance metadata are stored in the existing no-backup Retirement database. Raw workbook bytes, formulas, filename, path and URI are never written to disk, database, navigation state, work requests or logs. No persistent document permission is taken. Input streams close on success/failure; retained archive byte arrays are cleared when their scopes finish. Managed-runtime/transient XML/string copies cannot be guaranteed erased from RAM. Restored picker callbacks are ignored; rotation/process death discards an unconfirmed review and requires selection again. Confirmed transactions remain readable after recreation.

The entire Retirement window uses `FLAG_SECURE`, including indirect displays of Epic values. The screenshot fixtures are hand-authored fictional amounts and labels; the native audit never screenshots a real workbook. Exceptions crossing the parser/UI boundary contain only safe enums, with no source exception cause or workbook value. Backup allowlists and the Fitness document remain unchanged.
