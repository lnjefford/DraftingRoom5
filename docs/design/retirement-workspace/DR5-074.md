## Engine and integration contract

`retirement/forecast/` provides detached immutable `ForecastInput`, `ForecastInputs.capture`, `RetirementEngine.calculate`, `ForecastCoordinator`, typed scenario deltas, tax/ACA/withdrawal policies, mortgage amortization and private result histories. Existing repository/domain/codec models remain authoritative. The clean, unreleased Retirement schema now distinguishes `ORDINARY`, `SOCIAL_SECURITY`, and `TAX_FREE` income rather than inferring Social Security from a name or boolean. It also persists HSA contributions, medical withdrawal cap, real home appreciation and market volatility scale. There is no development-data migration or Fitness schema change.

Capture reads the repository's one committed document, including its generation and plan revision. It copies sorted account/property/income/workbook values into immutable collections. Only included active ordinary accounts enter financial buckets; confirmed tax treatment chooses the bucket. Property and Epic wrappers and holdings never add a second balance. Account-type reference allocations are explicitly disclosed; imported security classifications are not sufficiently complete to infer custom holdings allocations. Unknown balance, invalid amounts, unsupported tax/ACA policy or incomplete/mismatched workbook returns typed `NeedsData` rather than plausible defaults. Unknown taxable basis uses the reference's disclosed 70% basis, except cash which uses 100%; supplied basis is capped to bucket value for realized-gain accounting.

The only accepted policy identifier is **finance-reference-v1**. Separate component IDs are `federal-2026-reference-v1`, `wi-2024-reference-v1`, and `aca-2024-fpl-step-reference-v1`. DR5-075 must expose this model identity and warnings; it must not label the output a current-law tax calculation. Unsupported states are rejected, rather than silently assigning zero. WI and the reference's AK/FL/NV/NH/SD/TN/TX/WA/WY zero-state-income-tax approximation are supported.

`calculate` always runs on `Dispatchers.Default`. The coordinator captures and publication-checks the repository on IO, observes committed changes, cancels/restarts old work with `collectLatest`, and publishes only a complete result whose request ID, generation and plan revision still match. Repository publication and writes share a process lock, preventing a write between generation checking and publication. Cancel/restart/close cannot publish a superseded result, even if a dependency ignores cancellation. Prior complete output remains explicitly `previous` in calculating/failure/cancelled states; it is stale. A result always carries its generation, which consumers must compare with the asset generation they display. No results or random seeds enter saved-instance state or ordinary backups.

Scenarios bind a typed single-setting delta to a base generation and plan revision. Preview makes a separate snapshot. Apply uses a generation CAS and appends a plan revision changing only that delta. Reuse the same explicit seed for base/scenario Monte Carlo comparisons; independent seeds introduce sampling noise. Retirement-age changes that conflict with the accepted workbook require an updated workbook, rather than local Epic overrides.

## Numerical and annual conventions

- Input/persisted money is integer cents. Computation uses finite Double real dollars, with HALF_UP rounding only when returning `Money`. Outputs are not reinflated. Individual assets retain the existing 100 trillion-cent input ceiling; every publication and material intermediate is bounded to 90 trillion dollars (9 quadrillion cents, below the exact-integer Double ceiling). Excessive growth fails safely; no wrapping Long conversion, infinity, saturation or invented success is returned.
- Current age is completed birthdays at `referenceDate`, including leap-day behavior from `java.time.Period` (a February 29 birth advances age on March 1 in non-leap years, matching the reference age calculation). Index zero is the current-age boundary. A step at age A applies that year's flows and publishes closing balances at A+1; the final end-age boundary has no extra year of spending. Retirement begins when whole-year age is at least retirement age. There is no partial-year proration or exact 59.5-year eligibility claim.
- Split contributions occur before growth only before retirement. Taxable contributions increase basis. Empty buckets default to the reference cash return (0.5% real). Equity-return settings anchor US stocks at `expectedReturnBps`; the difference from 650 bps shifts US/international/REIT/crypto means, leaving bonds/cash unchanged. Volatility scale multiplies all market standard deviations. Defaults reproduce the pinned reference.
- Market returns are arithmetic normal, with the reference six means/deviations and correlated five-asset covariance; crypto is independent. A negative market tail is floored at zero **before** withdrawals, preventing a negative bucket from consuming other assets' cash. This is a deliberate correction of a reference edge case below -100%.
- Income streams use closed start/end ages and offset retirement spending. Social Security provisional-income taxation and pension ordinary taxation match the reference. Surplus income is not reinvested; the reference still withdraws its modeled income tax. RMDs transfer traditional assets into taxable cash/basis before growth, creating taxable income but no new wealth. The reference table covers ages 73–120 only; birth-cohort law, older-age extension, survivor/spousal rules and qualified-distribution exceptions are not claimed.
- Withdrawals follow taxable, medically capped HSA, Roth at 60, traditional at 60, then any explicitly supplied non-retirement bucket at 60 (property remains separate). Internal ordered/capped rules are supported without a Strategy screen. Gains use the current aggregate gain ratio and returned basis is removed after withdrawal. HSA caps represent qualified medical spending assumptions, not an eligibility determination.
- Property value grows at the selected real appreciation. Its fixed nominal mortgage payment amortizes monthly with the reference's un-deflated mortgage-balance approximation; non-amortizing payments do not fabricate paydown. Ownership applies to both value and debt. Spendable equity floors at zero, while existing repository totals/history continue to retain negative equity. Estimate-range uncertainty is a single first-year normal shock, capped at 20% sigma with a -50% annual appreciation floor. Home sale occurs at the retirement boundary **before** that year's market growth. Spending must already include housing/mortgage/rent; payments are not additionally subtracted. No sale costs or home-sale tax model is invented. A home already held after a past retirement boundary is not retroactively sold.
- Epic uses saved annual workbook net-pretax and after-tax values only, divided by `(1+inflation)^elapsedYears`. All years through retirement (or horizon if earlier) must exist, and the workbook projection date must match the plan retirement birthday. Missing years, negative spendable rows, past-retirement unresolved holdings and mismatched dates require data. No missing-year interpolation, terminal extension, fallback local growth/tax or manual sale setting is allowed. The workbook after-tax value transfers into taxable cash/basis **after** market growth in the retirement year. Both remaining Epic pretax and after-tax histories become zero after sale; the reference retains a stale after-tax display history, intentionally corrected here.
- Epic uncertainty uses the reference mean-reverting log deviation (persistence 0.70, innovation sigma scaled by `sqrt(1-.7²)`, variance correction), with input sigma capped at 10%. This caps modeled sigma, not every possible realized draw; it is not a hard percentile bound. Missing history means a disclosed deterministic schedule. Property, Epic and market RNG streams are separate so unrelated scenario edits do not shift market draws.

## Explicit tax/ACA approximation and primary-source review

This item selects the architecture's permitted **explicitly labeled reference approximation**, preserving its outputs rather than silently upgrading law. Source hashes are unchanged. On 2026-09-20, primary-source review confirmed that matching the reference is not equivalent to implementing all contemporary rules:

- [IRS Rev. Proc. 2025-32](https://www.irs.gov/irb/2025-45_IRB) supplies the 2026 federal bracket/deduction/LTCG anchors. The reference does not allocate unused ordinary standard deduction to gains and limits its NIIT model to LTCG; extra deductions, credits and exclusions are outside this engine.
- [Wisconsin DOR retired-person guidance](https://www.revenue.wi.gov/Pages/FAQS/pcs-retired.aspx) describes Wisconsin's Social Security subtraction and retirement-specific provisions. The pinned reference instead taxes its computed federal taxable Social Security in WI, uses 2024 brackets, and omits standard-deduction phaseout and retirement subtractions. These remain named approximations, not contemporary-law certification.
- [IRS premium-tax-credit FAQ](https://www.irs.gov/affordable-care-act/individuals-and-families/questions-and-answers-on-the-premium-tax-credit) describes household MAGI and the temporary 2021–2025 expansion. The reference's 2024 FPL and piecewise constant percentages, exclusion at exactly 400% FPL in cliff mode, and below-133% behavior are frozen model semantics. `EXTENDED` is an alternate assumption, not a claim of current eligibility. Household membership, employer/Medicare eligibility and reconciliation are not modeled.

ACA is calculated before age 65 using ordinary streams + 85% of SS + spending need times the **cross-path median** taxable gain ratio. It excludes the actual traditional withdrawal/RMD MAGI feedback. Premium credit reduces spending need. Tax funding uses two iterations and a final withdrawal, exactly as the reference. It does **not** converge fully at ordinary effective tax rates. Every result carries actual recomputed tax, the positive difference from funded tax in `TAX_RESIDUAL`, the maximum gap and count of affected path-years. `taxFundingConverged` is false above one cent; a mandatory warning explains that modeled success does not certify full tax funding. Tests independently reconcile the gap instead of widening monetary tolerance to conceal it.

Failure means a reference-model unmet spending amount over $0.01 in any retirement year, even if terminal assets remain positive. `depletionAge` returns `endAge + 1` for a successful path; this is a sentinel, never a predicted failure age. Diagnostics record first failure age, unmet dollars, retained assets and whether asset exhaustion or access/rule limits prevented funding. They report observations, not a qualitative score or an unsupported claim that a particular market event caused failure. Tax residuals are separately visible; users must not mistake reference success for a fully tax-funded probability.

## Randomness, memory and tolerances

Tests use explicit Long seeds. Production obtains an unpredictable seed from `SecureRandom`, then uses `java.util.Random.nextGaussian` with the fixed Cholesky transform for simulation (not cryptographic use). Market draw order is year/path/asset; property is property/path; Epic is path/year. Property seed is XOR `0x50524f50`, Epic XOR `0x45504943`. The result records its transient seed for repeat/scenario comparisons. Same seed and engine version reproduce Kotlin draws; NumPy's equal numerical seed does **not** imply identical draws.

Shared seeded NumPy asset-return and standard-normal tapes bridge the runtimes. `forecast-cases.json` contains only fictional inputs. `forecast-expected.json` freezes actual source-engine output; `verify_forecast.py` checks source hashes, denies network/config/database/personal-file access and never rewrites goldens unless explicitly run with `--write`. Initial recording and the additional uncertainty fixture were reviewed in this task. Ordinary test/build validation uses read-only mode.

The engine retains 13 primitive histories and bounds `paths × (years+1)` to one million, with paths ≤20,000 and horizon ≤130 years. A second allocation guard limits a single history to one third of the device process heap (current result, prior result, and app/working overhead each have a reserved share); oversized requests fail before allocation. A 10,000 ×50-year result retains 53,040,000 history bytes; the largest permitted result retains 104 MB plus working state, collections and JVM overhead. No pre-generated market cube is retained in production. Cancellation is checked each year and every 128 paths in major loops, before final publication. Host budget is 10 seconds; the constrained Android emulator audit budget is 30 seconds with a live main-thread heartbeat. DR5-075 should share one coordinator across the workspace, compare base/scenario sequentially with the same seed, retain at most the base and replacement histories, and request fewer paths for horizons exceeding a device budget. These are verification budgets, not a physical-device performance guarantee.
