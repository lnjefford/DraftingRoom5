# DR5-072 — Automatic property values and property flows

Status: complete in the accumulated, uncommitted Phase 9 checkout. The released app remains v0.26.1.

## Delivered behavior

- Accounts keeps Properties as its final account section. A property row shows the accepted value, exact-cent owned equity, source, and scoped attention state, and opens directly to Property detail. There is no Properties overview or rental-priorities model.
- Add asset opens one private native property task. Users can authenticate and enter or replace their own RentCast key, search a full address, review the provider's matched address, facts, current estimate, 85%-confidence range, comparable count and as-of date, then confirm before anything is created.
- Manual fallback remains available without credentials. Manual property copy explicitly says that values change only when the user appends a dated valuation and never claims automatic updates.
- Property detail shows value/range, mortgage, ownership, exact equity, forecast inclusion, source, freshness, facts/comparable metadata, explicit refresh, history and edit. Edit supports address, current mortgage balance and forecast inclusion; the automatic path also reaches private credential replacement.
- Accepted provider and manual values append snapshots. Provider failure appends no valuation, preserves the last accepted value, and records an affected-property status, safe error and attempt time. History is never overwritten.
- Each automatic property gets unique, connected-network, battery-not-low WorkManager work with a seven-day interval, seven-day initial delay and bounded exponential retry. Android scheduling is intentionally approximate. Explicit refresh uses the same guarded publication path.

## Security and provider boundary

`RentCastNativeProvider` reuses the DR5-070 `ProviderCredentialVault`, Android Keystore key and no-backup atomic encrypted store. The key is entered in a FLAG_SECURE task after device credential authentication; the field disables saved state, autofill, content capture and personalized keyboard learning. Only the opaque property UUID enters WorkManager data.

`SecureRentCastTransport` permits only fixed HTTPS GETs to `api.rentcast.io` and enum-owned `/v1/properties` and `/v1/avm/value` paths. It disables redirects and caches, bounds time and response size, sends `X-Skip-Logging: true`, and returns only redacted local failure categories. Addresses are query inputs and therefore reach RentCast directly as required for lookup; they are never logged by the app. API keys, responses and addresses are absent from fixtures and screenshots except fictional values.

The implementation follows the provider's current documented property-record and value-estimate endpoints, `X-Api-Key` authentication, `price`/range response fields, subject-property metadata and comparable list. No companion, backend, rental estimate or forecast behavior was added.

## Domain and persistence

Money crosses provider and form boundaries through decimal text and publishes as checked integer cents. `Property.equity()` subtracts mortgage cents before applying ownership basis points with explicit HALF_UP rounding. Automatic revisions bind the accepted RentCast property identity and credential profile; manual revisions cannot carry either. The strict codec and state validator enforce these invariants.

Provider creation atomically writes wrapper, property, initial valuation and ready metadata. Refresh publication checks the repository generation and property revision so older network results cannot overwrite edited state. SQLite's existing append-only valuation ledger and atomic document transaction remain authoritative.
